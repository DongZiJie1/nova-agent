# Internal session lifecycle and records

These are built-in APIs only. There is no settings, shell command, or extension configuration surface for lifecycle subscriptions.

`core/lifecycle-hooks.ts` provides a process-local `lifecycleHooks` registry. Register an event with `name`, `handler`, and a positive `timeoutMs`; the returned function unsubscribes it. Events are `session_start`, `turn_end`, `agent_idle`, `before_compaction`, and `session_end`. Subscriptions run sequentially in registration order. Failures and timeouts are logged to stderr and processing continues. Handlers receive the session, reason where applicable, and an AbortSignal. Asynchronous handlers must observe that signal: a timeout stops awaiting a handler but cannot forcibly cancel JavaScript or interrupt synchronous CPU work.

Start is emitted once per runtime, independently of extension reload. Turn-end runs after message persistence and completion traces. Idle runs after retries and automatic compaction settle. Both manual and automatic compaction run the pre-compaction event. Runtime quit, new, resume, import, and fork await the old session's end hooks before disposal. SDK hosts that own an AgentSession directly should await `endLifecycle("quit")` before calling synchronous `dispose()`.

`getSessionStats()` and local records share aggregation over every session entry, including other branches and compacted history. `startedAt` is the session header timestamp; duration is wall time from that timestamp through `endedAt` or now, including time between resumes. `lastActivityAt` is the latest persisted entry timestamp. `turns` counts persisted assistant responses (one model/tool round, including partial or failed responses), rather than user prompts. Tool distribution counts assistant tool-call blocks, without double-counting results. Tokens and costs include assistant, tool-result, compaction, and branch-summary usage. Built-in memory writers call `recordMemoryWrite()` only after a successful write; this persists a `nova.memory_write` marker.

For persisted sessions, `<session>.jsonl.record.json` holds one current record per session file, with timing, counts, tokens, cost, reason, and `abnormalEnd`. End records are atomically replaced with mode 0600. Resuming and then closing a session updates its existing record. In-memory sessions never create records. A newly created empty session can have a record even when the session manager has not yet flushed its JSONL.

`<session>.jsonl.active.json` records the owning PID while a runtime is active. At startup, each local session directory is reconciled once per process. Live owners are skipped. Missing end records and stale owners are recovered from session entries; a stale owner supersedes an earlier normal record if a resumed session crashed. Recovery is idempotent, does not run end hooks, and isolates unreadable/malformed files. An abnormal end time is the last persisted activity, an estimate rather than the instant of process death. PID reuse can conservatively defer recovery until a later startup. Scan roots include the configured agent directory and a custom session directory. All data stays local; no telemetry is added.

Studio waits for logical-agent stop acknowledgements. On application exit it closes the shared host's input, allowing Nova's existing RPC EOF shutdown to finish. Independent processes use the same EOF path. After 15 seconds an unresponsive process is killed and its session is recovered at a subsequent startup.
